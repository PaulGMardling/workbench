# Delegated accessibility work

Read this only when assigning work to other agents. Solo investigation follows
the [skill](../SKILL.md) without a coordinator ceremony. Use the
[evidence guide](evidence-contract.md) for reporting and verification rules and
[implementation scope](remediation-and-delivery.md#implementation-scope) for
source-edit authority; delegation creates neither access nor permission.

## Assign only useful independent work

The assigning agent owns scope, dependencies, resource allocation and the final
explanation. Delegate bounded questions that benefit from separate context,
not fragments of one continuous code trace. Roles are responsibilities, not a
minimum headcount:

| Responsibility | Bounded output |
| --- | --- |
| Standards research | Applicable W3C WAI requirements and version-matched contracts, including conflicting evidence; no inferred runtime observations |
| Runtime investigation | Exact scenario, versions, observations and harness limits; no inferred standards obligations |
| Code investigation | Decisive cause/caller trace or separately identified in-scope findings, with alternatives and guards checked |
| Challenge | Try to disprove a consequential conclusion and suggest a discriminating check; do not patch |
| Implementation | Only the authorised fix in the owning workspace, with actual changes and focused regression results |
| Verification | Check the actual fixed revision after implementation, not another agent's assurance |

Assign implementation before verification; do not run writers against the same
files concurrently. The owning publisher retains any delivery responsibility.

## Independence and resource ownership

For independent first passes, supply the same neutral request/target without
sharing conclusions. A later challenger may intentionally receive a provisional
diagnosis, but that is not an independent initial pass. Resolve disagreements
against evidence, not votes, and keep unresolved objections visible.

Assign one owner at a time for a shared browser/profile, AT session, fixture,
server, checkout or writable artifact. Different tabs/agent names do not prove
isolation. Serialize access unless separate instances and state are verified.
Hand off the current state, target/build, reset steps and ownership; do not reset
another worker's environment or terminate their processes.

Workers report directly to the assigning agent, not siblings. Route dependencies,
scope changes and blockers to that owner rather than taking over another task.
Workers must not delegate further unless explicitly authorised by the owner.

## Assignment and return

Give each worker the original request, exact bounded question, target/revision,
scope/exclusions, permitted actions, owning workspace/resources, relevant
guidance and a stop condition. Include existing fix authority for implementation,
and the fixed revision for dependent verification. Availability is not authority;
do not ask workers to infer missing permissions.

Return the answer, source/observation locators, actual commands/results, scope
inspected, counterevidence, uncertainty and blockers. Report resource state and
any changes before handing ownership back. Use natural claim/evidence labels
only when they help distinguish items; no allocated IDs, ledgers or report
objects are required.

The assigning agent checks decisive evidence and integrates the result into an
ordinary developer explanation, not a transcript dump. If delegation is
unavailable, work sequentially where permitted and disclose lost independence.
If independence is explicitly required, leave that requirement incomplete.
Persist material results in authorised task storage before declaring the
assignment finished so a later handoff need not depend on a live agent handle.
